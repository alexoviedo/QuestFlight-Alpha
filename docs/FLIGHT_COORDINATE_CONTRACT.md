# Product flight and scenery coordinates

The authored product uses WGS84 ellipsoidal azimuthal equidistant (AEQD), centred at the serialized KBDU origin: latitude 40.03936527°, longitude −105.22608958°. Its definition is `+proj=aeqd +lat_0=40.03936527 +lon_0=-105.22608958 +datum=WGS84 +units=m +no_defs`, as defined by `tools/aerial_surface/geospatial_frame.py`. Unity X/Z represent the projected east/north axes. They are not ECEF tangent-plane coordinates or UTM13N deltas. Source UTM rasters are transformed by the existing authoring tools; this correction does not regenerate scenery.

Unity Y is the authored source MSL elevation minus origin MSL elevation (1611.7824 metres). It does not contain Earth-curvature sag. `FlightFrameConversions` uses bounded WGS84 Vincenty geodesic inverse/direct calculations to implement this same ellipsoidal AEQD projection. Position tests use independent PROJ fixtures at the airport, runway ends, representative distant points and map corners; the supported map is 24 km square. The acceptance tolerance for the same reference point is 0.05 m, separately from source survey accuracy and terrain approximation.

JSBSim 1.3.1 represents `ic/h-sl-ft` and `position/h-sl-ft` as radius minus the ellipsoid radius on the same geocentric ray. Its default native ground callback instead places contact at geodetic elevation and returns geodetic AGL. The product adapter converts geodetic/source MSL numerical elevation to the native radial ASL at reset, then converts radial ASL back at every capture. Those conversions derive the ellipsoid position and sea-level radius, and invert that relation; they are not a distance-based curvature adjustment. Terrain elevation sent to the native callback remains the source MSL numerical elevation at the sampled projected XZ.

The native ellipsoid uses WGS84 axes. Source MSL elevations are used as the common simulation height values at the geodetic/native boundary; this is an explicit numerical datum convention, not a surveyed geoid/ellipsoid conversion. No geoid separation grid is bundled and no survey accuracy claim is established by these tests. Installing a different real-world height datum requires a separately evidenced input contract rather than a visual height offset.

Native NED velocity uses the aircraft's physical local north/east/down basis. The adapter uses the AEQD projection Jacobian at the actual latitude, longitude and altitude to produce projected world velocity. The shared wind field is authored in the projected world axes, so its inverse Jacobian supplies physical NED wind before every reset and step. Projected true-north orientation supplies the attitude basis; projection scale or shear never deforms the aircraft. Body rates retain their FRD-to-Unity sign convention. Authored spawn rotations and recovery directions are grid bearings and are converted to true heading at the respective position. A numerically specified flight heading remains a true heading.

Reset wind is a native transaction: configure physical NED wind, resolve airspeed through JSBSim, initialize ground velocity as air plus wind, then execute RunIC. A zero-CAS reset requests a stationary start and truthfully reports wind-relative airspeed. Native JSBSim remains the only flight authority, with the same API2 ABI. These coordinate changes do not write the tracked camera or rebuild the serialized product hierarchy.

Validation distinguishes these tolerances and scopes:

- Forward/inverse reference coordinates: 0.05 m maximum round-trip error over the named fixtures.
- Actual native reference-point reset presentation and ground-callback AGL: 0.01 m at origin, both runway directions and the three distant audit points. The first native step must remain finite and within 0.02 m of the starting height in the zero-power fixture.
- Immutable far visible mesh versus its separate query surface: the three named audit samples differ by approximately −0.0446, +0.4117 and +0.2233 m. The retained 0.5 m bound applies to these three samples only. The surfaces have different resolution/smoothing and these values do not establish a map-wide centimetre contact contract. Source approximation limits remain their own authored records.
- Suspension, wheel geometry, native landing/taxi on slopes, collider appearance, comfort and headset visuals require their separate integration and physical checks. A reference-point reset is not a complete touchdown or worn-headset acceptance test.

Recorded remediation evidence is local under `.questflight_codex_audit/status/M04-results.json`, with real packaged Windows native execution and the original audited mesh decoder. `ProjectedFlightFrameEditModeTests` verifies the actual C# adapter, independent PROJ coordinates, physical velocity/wind basis and native backend against the serialized terrain asset. Android compilation, simulator stereo inspection and final Quest acceptance are recorded separately and cannot be inferred from offline arithmetic.
